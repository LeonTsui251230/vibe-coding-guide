## 📌 写在前面

你可能听过这些说法：

> "不会写代码也能做 App。"
> "AI 帮我写完了整个项目。"
> "Vibe Coding 让每个人都成为开发者。"

这些话**一半是真的，一半是坑**。

这一篇指南的目的，不是让你觉得"AI 无所不能"，而是给你一套**能真正落地的心法和工作流**：让你用 AI 把脑子的想法，稳稳当当地变成能用的产品，而不是生成一堆跑不起来、改不动、最后只能删掉的代码。

**这篇指南适合谁：**

- 完全不懂编程，但想做点东西的人；
- 会一点、但搞不定完整项目的人；
- 想做独立产品 / 小程序 / 小工具赚点钱的人；
- 团队里负责想法和产品的"非技术"角色。

**这篇指南不适合谁：**

- 想找"一键生成、零参与"的魔法（不存在）；
- 拒绝学习任何基础概念、连文件夹都不想看的人。

**我的主张（为什么敢叫"全网最好"）：**

市面上多数教程要么太"程序员黑话"，要么太"营销吹水"。这篇把**道（理念）、法（流程）、术（技巧）、器（工具）**四层拆开讲，给你能直接抄的提示词、能照做的步骤、以及真实踩过的坑。读完你能上手，而不是只会喊"哇好厉害"。

## 一、什么是 Vibe Coding

### 1.1 一句话定义

**Vibe Coding（氛围编程）= 你用自然语言描述想要什么，AI 负责把代码写出来，你负责判断对不对、好不好、往哪走。**

你不再死磕语法，而是像给一个很能干但容易跑偏的实习生下 Brief：说清楚目标，看它交活，不对就打回重做。

这个概念由 AI 领域的 Andrej Karpathy 在 2025 年初提出。原话大意是：你"沉浸在氛围里"，用对话的方式和 AI 一起把东西做出来。

### 1.2 它和"传统编程"的区别

| 维度 | 传统编程 | Vibe Coding |
|------|---------|------------|
| 谁写代码 | 你 | AI |
| 你需要的技能 | 语法、框架、调试 | 表达清晰、判断力、常识 |
| 上手速度 | 慢（几个月起） | 快（当天就能出东西） |
| 上限 | 高，可控 | 取决于你"带人"的能力 |
| 下限（做砸了） | 自己背锅 | 也自己背锅 😅 |

### 1.3 它能做什么 / 不能做什么

**能做：**
- 网站、小程序、小游戏、浏览器插件、自动化脚本、数据爬取、简单后端；
- 帮你读代码、改 bug、写文档、做设计稿；
- 把"大概的想法"快速变成能点的原型。

**不能做（务必清醒）：**
- 替代你对"做什么、为谁做、好不好用"的判断；
- 保证一次生成就完美（几乎不可能）；
- 在不懂任何概念的情况下，长期维护一个复杂系统；
- 自动帮你"想清楚商业逻辑"——这恰恰是你人类该干的活。

### 1.4 最常见的三个误解

- **误解一："我不用学任何东西。"**
  错。你要学的是**怎么把需求说清楚**、**怎么判断 AI 做对了没**。这比学语法难，也比语法重要。
- **误解二："AI 写的代码我不用看。"**
  大错。你不看，就等于把房子钥匙交给一个你从没见过的人。后面出问题你完全无从下手。
- **误解三："做不出来是 AI 不行。"**
  多数时候是 Brief 没说清、目标没拆细、验收标准模糊。锅主要在你这边的"管理"。

## 二、三条核心心法（先看这个）

如果你只记住三句话，就是这三句。它们是后面所有方法的根。

### 心法一：规划先于编码

> **在让 AI 写第一行代码之前，先把"做什么、给谁用、长什么样、第一步做啥"写成三五行人话。**

AI 不会读心。你脑子里模糊的想法，它只能猜。猜错了，它就给你一堆"看起来对、其实跑偏"的代码，改起来比从头写还累。

**反例：** "帮我做个电商平台。" —— 太大、太模糊，AI 会给你一个 5000 行的怪物。
**正例：** "做一个卖二手书的微信小程序：用户能发书、浏览、私聊砍价。先做'发书+列表'这一个小功能。"

### 心法二：把大象拆成蚂蚁

> **永远一次只让 AI 做一件小事。做完、跑通、确认没问题，再做下一件。**

AI 一次能做好的事，大概等于"一个明确的、十分钟能验证的小功能"。你让它"把整个系统都做了"，它就会开始自由发挥，最后你拿不到能用的东西。

拆得越细，翻车概率越低。一个"做小程序"的大任务，至少拆成：搭框架 → 写发书表单 → 写列表页 → 写详情页 → 接数据库 → 加私聊……每一步单独验证。

### 心法三：你当司机，AI 当副驾

> **最终决定权、方向感、验收标准，必须握在你手里。AI 是执行力，不是决策力。**

AI 会非常自信地胡说八道，会"贴心"地改了你没让它改的东西，会在你没注意时引入 bug。**所有它产出的东西，你都要能说清楚"这是什么、为什么对"。**

做不到这点，你不是在 Vibe Coding，你是在 Vibe Gambling（氛围赌博）。

## 三、道：理念与原则

"道"是你做所有决定时心里那把尺。六条原则：

1. **可控优先于炫技。** 宁可功能少而稳，不要花哨但崩。用户要的是"能用"，不是"技术牛"。
2. **可追溯、可回退。** 每做一步都能回到上一步。所以要用版本管理（git），别在本地瞎改不存档。
3. **小步验证，频繁运行。** 写完一小段就跑一下，越早发现问题，代价越小。别等写完了才发现整页报错。
4. **说人话，说细节。** 给 AI 的指令越具体越好。模糊的 Brief = 随机的结果。
5. **你定义"完成"。** "做完了"不是 AI 说做完了，是你亲眼看到、亲手点过、确认符合预期。
6. **产品思维 > 技术思维。** 用户为什么用、愿不愿意付钱、能不能找到，比"用了什么框架"重要一万倍。这也是你作为非技术者的真正优势——你懂人和需求，AI 只懂代码。

## 四、法：标准工作流（从想法到上线）

把心法落成六步走。每一步都给做法 + 可直接用的提示词。

### 阶段一：想清楚（产出：一句话需求 + 用户画像）

不要急着写代码。先回答三个问题，写成文档（哪怕就几行）：

- **给谁用？** 例如：想做副业的大学生。
- **解决什么具体问题？** 例如：找不到便宜的二手教材。
- **第一步最小能用的版本（MVP）做哪一块？** 例如：只能发书 + 看列表。

> 💡 非技术者最大的优势是"懂用户"。这一步你比 AI 强，认真做。

**提示词示例（让 AI 帮你梳理）：**
```
我想做一个[产品或服务]，目标用户是[谁]，主要帮他们解决[什么问题]。
请帮我：
1. 用三句话总结出核心价值；
2. 列出最该先做的 3 个最小功能（MVP）；
3. 指出这个项目最容易死的 2 个风险。
不要写代码，只做产品分析。
```

### 阶段二：定方案（产出：技术选型 + 页面清单）

让 AI 给你一个"小白能懂"的技术方案：

- 用什么做前端（网页 / 小程序 / App）；
- 数据存哪（最简单往往是用现成的云服务或本地文件）；
- 需要几个页面 / 界面。

**提示词示例：**
```
基于上面的 MVP，帮我选一套最适合零基础、最快上线的技术栈。
要求：部署简单、不用自己买服务器、文档多。
请列出：用什么做界面、数据怎么存、需要几个页面，以及每一步大概做什么。
用大白话解释，别堆术语。
```

### 阶段三：拆任务（产出：任务清单）

把方案拆成 5–10 个"单步能验证"的小任务。例如：

1. 搭好项目空壳，能打开一个空白页；
2. 做出"发书"表单（标题、价格、图片）；
3. 做出"书列表"页，能看到提交的内容；
4. 把数据存起来（刷新不丢）；
5. 加一个"详情"页；
6. 美化一下样式；
7. 部署上线。

**提示词示例：**
```
把下面这个项目拆成不超过 10 个开发任务，每个任务满足：
- 一次只做一件事；
- 做完能在浏览器/手机上立刻看到效果；
- 用一句大白话描述。
项目：[粘贴你的方案]
```

### 阶段四：逐步实现（一次一个任务）

**严格一次只做任务清单里的一项。** 做完、跑通、你确认没问题，再让 AI 做下一项。

每一步的提示词模板：
```
当前项目：[简单背景]
请只完成这一个任务：[具体任务，如"做出发书表单"]。
要求：
- 不要改动其他已有功能；
- 写完后告诉我怎么运行看效果；
- 如果有多种做法，先选最简单的。
```

⚠️ **关键纪律：每次任务完成后，让 AI 自己总结"我改了哪些文件、加了什么"**，你留存。这是你日后排查问题的地图。

### 阶段五：测试与调试

AI 写的代码十有八九有 bug。别怕，调试也是流程的一部分。

- **报错先贴给 AI：** 把完整的红色报错信息复制给它，说"这是报错，帮我定位并修"。
- **现象描述清楚：** "点提交按钮没反应"比"不好使"有用一百倍。
- **改一处验一处：** 它说修好了，你再跑一次确认，别一批改十个然后不知道哪个坏了。

### 阶段六：上线与迭代

小功能跑通后就可以上线（部署），早点上线的好处是：真实用户会告诉你哪里真有问题，比你自己瞎猜强。

上线后按"用户反馈 → 改一小点 → 再上线"的循环走，别追求一次完美。

## 五、术：提示词与实战技巧

"术"是手上功夫。这部分最值钱。

### 5.1 写好提示词的七条铁律

1. **给背景，不要默认它懂。** 开头一句话交代项目是什么。
2. **说清"只做这一件"。** 防止 AI 顺手改乱其他东西。
3. **说清"完成长什么样"。** 描述预期结果，而不是只说动作。
4. **指定最简单方案。** "选最简单的实现，别引入我没听过的库。"
5. **要它解释。** "写完后用三句话说明你做了什么、怎么运行。"
6. **要它自查。** "提交前先自查一遍明显错误。"
7. **一次改一点。** 不要一轮让它改十个问题。

### 5.2 四个高价值提示词模板（可直接抄）

**模板 A：从零启动**
```
我想从零做一个[产品]。我是零基础。
请帮我：①选最简单技术栈 ②列出前 5 个开发任务 ③写出任务 1 的完整代码并说明怎么运行。
每步用大白话。
```

**模板 B：改 bug**
```
我的项目报错了，完整报错如下：
[粘贴报错]
项目背景：[一句话]
请：①用大白话解释这是什么错 ②给出最小修改方案 ③改完告诉我怎么验证修好了。
不要顺手重构其他代码。
```

**模板 C：加功能（防跑偏）**
```
在当前项目里新增一个功能：[功能描述]。
严格要求：
- 只新增这个功能，不动已有逻辑；
- 保持和现有风格一致；
- 写完说明新增了哪些文件、怎么测试。
```

**模板 D：让 AI 当审查员**
```
请站在"挑剔的用户"角度，审查我这个[页面/功能]：
列出 5 个最可能让用户困惑或流失的点，并给改进建议。不要写代码。
```

### 5.3 调试：AI 写出 bug 怎么办

- **不要让它"全部重写"。** 重写容易引入更多问题。让它"定位并最小修改"。
- **报错即事实。** 红色报错是唯一真相，贴全，别自己翻译。
- **二分法。** 上一版还好好的，这版坏了——那问题就在这版改的地方，让 AI 只看这块。
- **回退是常态。** 改坏了就退回上一个能用的版本（这就是为什么要版本管理）。

### 5.4 版本管理：git 是你的安全网

你不用懂 git 原理，记住三件事就够：

- **频繁存档：** 每完成一个小任务，就"存一次档"（commit）。
- **能回退：** 改崩了，回到上一个存档。
- **别怕：** 很多 AI 编辑器内置了"一键存盘/回退"，点按钮就行。

> 实在不想碰命令行，用带图形界面的工具（如 VS Code 的源代码管理面板、或 Cursor 内置的），点几下就存档。

### 5.5 避坑清单（新手最容易死的 10 个坑）

1. 一上来就让 AI "做个 XX 系统"——太大，必崩。
2. 不看 AI 写的东西，假装完成了——后面无解。
3. 让 AI 一次改十个问题——不知道哪个坏了。
4. 没有存档习惯，改崩了无法回退。
5. 追求"最牛技术栈"而不是"最简单能上线"。
6. 忽略"用户为什么用"只沉迷"功能多"。
7. 把私密信息（密码、密钥）写进代码还传上网。
8. 抄别人项目不读就跑——跑不起来还不知哪错。
9. 遇到报错就换工具——问题在 Brief，不在工具。
10. 做完不上线、不上线不找用户——永远在"自嗨"。

## 六、器：工具清单与选型

"器"是武器。下面分类列出，并给**零基础推荐组合**。

### 6.1 编辑器 / IDE（你写 Brief、看结果的地方）

| 工具 | 特点 | 适合 |
|------|------|------|
| **Cursor** | 专为 AI 编程设计的编辑器，对话改代码很顺 | 想认真做项目的人 |
| **VS Code + Copilot** | 免费友好，插件多 | 想先用免费方案 |
| **Windsurf / Cline** | 类 Cursor 的 AI 编辑器 | 想多比较 |
| **WorkBuddy 类对话式 Agent** | 不用开编辑器，对话就能让 AI 建项目、改文件 | 完全不想碰代码界面的人 |

> 非技术者建议：**先从"对话式 Agent"或 Cursor 入手**，它们能直接帮你建文件、跑命令，你主要动嘴。

### 6.2 AI 模型（帮你写代码的"大脑"）

主流可选：GPT 系列、Claude 系列、Gemini，以及各家国产大模型。
**选型建议：** 写代码逻辑强的模型（如 Claude、GPT-4 级）做主力；不同模型换着问，有时这个答不上那个答得上。新手不用纠结，先用一个顺手的。

### 6.3 辅助工具（让产品完整）

- **设计：** Figma（界面设计）、Canva（封面/海报）—— 不会画也能出图。
- **部署上线：** Vercel、Cloudflare Pages（网页一键上线）；微信开发者工具（小程序）。
- **域名：** 买个好记的域名（可选，前期可用平台免费子域名）。
- **图床 / 素材：** 免费图库（如 Unsplash）、图标库。
- **数据存储：** 前期用最简单的（本地文件 / 现成云服务），别一上来搞复杂数据库。

### 6.4 零基础推荐组合（照抄）

> **对话式 Agent（如 WorkBuddy）或 Cursor + 一个主力大模型 + Vercel/微信开发者工具上线 + Canva 做图**
>
> 这套组合的好处：不用自己配环境、不用买服务器、当天能看到东西。

## 七、入门七步（照做就出活）

> 目标：用最短路径做出你的第一个能跑的东西。

**第 1 步：装一个工具。** 选 6.4 里的组合，装上并登录。

**第 2 步：写一句话需求。** 例如："做一个记录每日喝水的小网页，能加一杯、看今天喝了几杯。"

**第 3 步：让 AI 出方案。** 用模板 A，让它选技术栈 + 列前 5 个任务。

**第 4 步：只做任务 1。** 让它"搭空壳能打开空白页"，跑起来你看一眼。

**第 5 步：逐个加功能。** 按任务清单，一次一个，做完确认再下一个。

**第 6 步：本地跑通。** 确认主要功能能用、不报错。

**第 7 步：上线。** 用 Vercel 等一键部署，拿到一个网址，发给朋友看。

🎉 到这就已经是"全网下过场"的 Vibe Coder 了。剩下的，是在真实使用里迭代。

## 八、实战案例：一个人做一款小程序

下面用一个贴近独立开发者的例子，串起前面的方法。

**背景：** 你想做一款"小区二手闲置"小程序，让用户发闲置、邻里互聊。

**阶段一（想清楚）：**
- 给谁：同小区住户。
- 解决：闲置扔了可惜、挂大平台太麻烦。
- MVP：能发闲置 + 看列表（先不做交易、不做登录）。

**阶段二（定方案）：** 让 AI 选微信小程序原生方案，数据先用小程序云开发（免服务器）。

**阶段三（拆任务）：**
1. 建小程序空壳，能打开；
2. 发闲置表单（标题、图、价格、描述）；
3. 列表页展示；
4. 详情页；
5. 云数据库存取；
6. 简单样式美化；
7. 真机预览。

**阶段四～五（实现+调试）：** 一次做一个，每个跑通再下一个。第 4 步卡了半天——把报错贴给 AI，它发现是字段名拼错，改一处就好。

**踩过的坑（真实）：**
- 一开始想"顺手把登录也做了"，结果卡三天。退回 MVP，先上线再补。
- 把测试用的真实地址写进了代码，上线前才想起来删。

**结果：** 两周做出能用的第一版，发给小区群，三天 40 人发闲置。验证了"有人用"，再决定加功能。

> 这个案例想说明：Vibe Coding 真正的壁垒不是"会不会写代码"，而是"能不能把一个想法拆清楚、小步快跑、用真实反馈迭代"。这恰恰是非技术者能赢的地方。

## 十、常见问题

**Q：我完全零基础，真能做出来吗？**
A：能做出"能用但不复杂"的东西。做不到"媲美专业团队的大产品"。把预期放在"小而美、能解决具体问题"上，成功率很高。

**Q：AI 写的代码安全吗？**
A：代码本身大多没问题，但你要避免把密码、密钥、隐私数据写进代码或传上网。上线前让 AI 帮你检查一遍"有没有敏感信息泄露"。

**Q：做出来怎么赚钱？**
A：Vibe Coding 解决"做"，不解决"卖"。赚钱靠你想清楚"谁愿意付钱、为什么"。这是你该补的课，AI 替不了。

**Q：选哪个工具最好？**
A：没有最好，只有最适合。新手先用一个"对话式 Agent 或 Cursor + 一个主力模型"，跑通一个项目比纠结工具重要。

**Q：项目做崩了怎么办？**
A：回到上一个存档（git 回退 / 工具的历史版本），别硬修。崩是正常的，会回退就不怕。

**Q：需要学编程吗？**
A：长期做复杂项目，懂点基础概念（什么是变量、函数、页面、接口）会让你"带人"更稳。但入门不需要，边做边学最快。
